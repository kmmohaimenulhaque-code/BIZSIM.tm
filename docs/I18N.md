# Languages in BIZSIM (1.7)

BIZSIM's interface is available in 15 languages, plus British English as a variant of English.
English (US) is the source language. **Every other language, including the British spellings, is
machine-assisted and has not been reviewed by a native speaker.** The app says so in Settings and
in About, and every language's status in `shared/locales.js` is `machine`.

| `bn` | Bengali | বাংলা | LTR | machine |

Status values: `notStarted`, `machine` (machine translated), `review` (review needed),
`reviewed` (reviewed by a fluent speaker), `release` (release ready). **Only change a status after
a fluent speaker has actually reviewed the language.** The status is shown to users.

## How it works

- **Library:** i18next + react-i18next, one `translation` namespace. Setup in `client/src/i18n/index.js`.
- **Resources:** `client/src/i18n/resources/<code>.json`, bundled with the app. English is loaded
  up front; every other language is its own chunk, loaded the moment it is chosen. Desktop and phone
  apps contain every file, so switching never needs the internet. In a browser, opening the language
  picker prefetches all languages in the background so the service worker caches them; after that,
  switching works offline too. A browser that has never opened the picker needs a connection the
  first time it loads a new language.
- **Fallback:** a missing key falls back to English. `en-GB` holds only spelling overrides and falls
  back to `en` for everything else.
- **Choice:** saved in `localStorage` under `bizsim.locale`. Detection order: saved choice, then the
  system languages in order (`navigator.languages`), then English. `en` with a UK-convention region
  (GB, IE, AU, NZ, IN, BD, PK, ...) maps to `en-GB`; `pt-*` maps to `pt-BR`; `zh-*` maps to `zh-Hans`.
  "Use the system language" in Settings forgets the saved choice.
- **Switching** happens immediately, with no restart. It never touches progress, cases, keys or
  settings (verified in the browser tests).
- **Document attributes:** `<html lang dir data-script>` follow the language. Season text that is
  still in English is wrapped in `lang="en"` so screen readers pronounce it correctly.
- **Plurals:** i18next suffixes `_zero _one _two _few _many _other`, using `Intl.PluralRules`.
  Arabic uses all six, Russian four, French/Spanish/Portuguese three, CJK and Indonesian one.
- **Formatting:** `client/src/i18n/format.js` wraps `Intl` for numbers, currency (never converted),
  dates, relative times, lists and language names. Bengali shows Bengali digits; Arabic shows
  Latin digits (what `Intl` produces for `ar`).
- **RTL:** the stylesheets use logical properties (`margin-inline-start`, `inset-inline-end`, ...).
  Under `:dir(rtl)` only directional icons are mirrored. Charts, QR controls, codes and numbers stay
  left to right.
- **Scripts:** `data-script` selects font stacks for Bengali, Devanagari, Arabic, Urdu (Nastaliq where
  installed) and CJK, with suitable line heights.
- **Errors:** shared code throws errors with a stable `code` (for example `package.damaged`); the
  interface shows them through `errorText()` in the current language.
- **AI output:** the client sends its language with live research and chat-builder jobs. The server
  sanitises it (`cleanLocale`) and appends `languageInstruction()` to the prompts, asking for all
  readable text in that language while ids, keys, sources, figures and quotations stay intact. The
  season records `contentLocale`. Wikipedia lookups stay in English.
- **Notifications** are written in the interface language and rescheduled when it changes.
- **Reports:** Latin-script languages use jsPDF's built-in fonts. Other scripts are rendered as HTML
  (with a strict CSP and no scripts) and turned into PDF by the desktop app's Chromium engine, by the
  browser's print dialog, or shared as an HTML file on phones.

## Season content (overlays)

The 200 built-in seasons are written in English and are **not** translated in 1.7. A translation is
an overlay file, `client/src/i18n/content/<locale>/<caseId>.json`, that replaces text fields by
stable id. Ids, scores, sources, URLs and historical flags are never taken from an overlay, so
progress, imports and comparisons are unaffected by language. Each overlay records `status` and
the `sourceRevision` (a fingerprint of the English text); if the English changes later, the season
shows that the translation may be out of date.

Sample included in 1.7: **one season, M-Pesa Mobile Money (`season-c138`), in Bengali and Spanish**,
both machine-assisted and unreviewed. Every other season shows its English text inside the
translated interface with a short note. The Explore page can filter to seasons translated into
your language.

## Tooling

```bash
npm run i18n:validate   # JSON, placeholders, markup, plural forms, arrays, unknown keys, overlays
npm run i18n:missing    # missing keys per language; keys the code uses that English lacks
npm run i18n:coverage   # coverage and status table (add -- --json for JSON)
npm run i18n:check      # all of the above plus unused keys and hard-coded interface text
```

Strings that must not be translated in code (developer errors) carry an `// i18n-ignore` comment.

## Adding or reviewing a translation

1. Edit `client/src/i18n/resources/<code>.json`. Keep every `{{placeholder}}` and markup tag
   (`<strong>`, `<link>`, `<code>`, `<em>`) exactly. No em dashes. Follow `docs/i18n/GLOSSARY.md`.
2. Run `npm run i18n:check` and `npm test`.
3. Only after a fluent speaker has reviewed the whole file, change its `status` in `shared/locales.js`.

Adding a new language means adding it to `shared/locales.js` and a resource file; 1.7 deliberately
adds no languages beyond the 15 listed.

## Known limitations in 1.7

- All translations are machine-assisted and unreviewed.
- Built-in season content is English, apart from the one-season overlay sample.
- Book principles and book titles in the library are shown in English.
- Progress messages and error text produced on the server (live research stages from the server,
  provider errors) can appear in English.
- Native dialog titles in the desktop app (folder pickers, save dialogs) are in English.
- The voice reader has English voices only; it is hidden for non-English text.
- PDF reports in non-Latin scripts depend on fonts installed on the device.
- Traditional Chinese (`zh-TW`, `zh-HK`) falls back to Simplified Chinese.
